# Scotty v0.4.0 — Board across projects

## What's changed

Open **All projects · Board** from the project list to browse tasks from all
registered projects together. The shared Board lives at `/board` and adds a
**Project** multi-select to the existing filters. Filter selections are stored
in the URL, so reloads and shared links preserve the view.

Cards show their project name. Opening a card takes you to its owning project's
detail view for viewing and editing. The shared Board supports priority and
recent-update sorting; creation, status changes, and manual ordering remain in
individual project views. Epics are included, and pinned or otherwise
unclassified items appear in Other. Demo is excluded from the shared Board;
archived tasks are hidden until Archived is enabled.

Projects load independently and refresh every 30 seconds. If one database fails,
available tasks remain visible with a project-specific error and a Retry action.

## WorkPost setup

Projects may share a Git repository while each keeps its own local Dolt database
at `<project>/.beads`. Connect the registry when starting Scotty:

```sh
export SCOTTY_PROJECTS_FILE="/path/to/WorkPost/воркспейс/конфигурация/projects.json"
export SCOTTY_PROJECTS_ROOT="/path/to/WorkPost"
# Preserve the existing BD_BIN and WORKPOST_BD_BIN settings for your wrapper.
npm run start
```

The registry uses a `projects` object keyed by project ID, with `name`, `path`,
and `beads_prefix` entries. Relative paths resolve from `SCOTTY_PROJECTS_ROOT`,
which defaults to two directories above the registry file for WorkPost's layout.
The registry is reread on requests; `archived_projects` are excluded. Manage the
project list in that file when registry mode is enabled. Without these variables,
Scotty continues to use its local project list.

Each CLI invocation sets the project's working directory and `BEADS_DIR`.
Scotty preserves `BD_BIN`, including wrappers that add `--include-comments` to
`bd show` for Beads 1.2.2. Tasks come from local Dolt through the CLI; Scotty does
not use `issues.jsonl` as its database. Duplicate IDs and hierarchy links are
isolated by project in the shared view.

Markdown artifacts, `spec_id`, and WorkPost metadata stay in the owning project.
This release does not add browser access to local Markdown links.

## Update this checkout

After obtaining the v0.4.0 source changes:

```sh
npm ci
npm run build
npm run serve
```

Restart an existing Scotty process after building. For the prepared local test
workspace, use `./test/start-scotty.sh` and open `http://localhost:3000/board`.
See [test workspace instructions](../../test/README.md). The three test databases
are local fixtures and are not included in Git; their presence on the development
machine does not seed them in a fresh clone.

## Validation

- Production build and TypeScript checks passed.
- Lint passed with one existing navigation warning in `hooks/use-notifications.ts`; the build reported existing filesystem-tracing warnings in the AI and publishing modules.
- Workspace regressions cover project filters, URL restoration, partial errors, project navigation, duplicate IDs, dependency and parent isolation, registry changes, and CLI database selection.
- Existing Board sorting and drag-feedback regressions passed.
- A browser check against three real local Beads 1.2.2 databases confirmed 21 visible cards, 24 with Archived enabled, and eight cards when filtering one project with Archived enabled.

This describes the local source release. Publishing a Git tag, a GitHub release,
or an npm package is a separate step.
